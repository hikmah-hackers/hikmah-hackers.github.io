## The short version

- We only collect what we need to run the class.
- **No ads, no tracking, no analytics, no cookies.** We never sell or share personal information for marketing.
- Student work is stored **privately**. Only the program's teachers can see it.
- Parents can ask to see, fix, or delete their child's information at any time by emailing **faiyajr@umich.edu**.

Hikmah Hackers is a free coding program run at Darul Uloom Michigan for students in grades 7–10. This policy covers this website (hikmah-hackers.github.io), the enrollment form, and the tools we use to collect and store student work.

## What we collect

### When a family enrolls (Google Form)

A parent or guardian fills in the enrollment form, which asks for:

- **About the student:** first and last name, date of birth, grade, school (optional), email and phone (optional), country, city, and time zone.
- **About the parent or guardian:** name, relationship to the student, email, phone, and preferred way to be contacted.
- **Background:** previous coding experience, which devices the student can use, internet reliability, how you heard about us, and anything else you choose to tell us.
- **Consent:** confirmation that a parent or guardian agrees to the student joining.

### When a student uses the class website

- **Student code:** each student gets a personal code from the teacher (like `KQM-4827`). It is used instead of an account, so students never create a username, password, or email login.
- **Submitted work:** the code a student submits, an optional note to the teacher, and the date and time. Each file is labelled with the student's name and grade.
- **Teacher feedback:** short notes the teacher writes about a student's work.

### The coding readiness quiz

Some students take a short quiz at the start, which records their name, grade, country, email address, and answers. We use it only to plan lessons at the right level.

## What we don't collect

- The website uses **no cookies**, **no analytics or tracking tools**, and **no advertising**.
- We don't ask for passwords, home addresses, photos, or location.
- The website's fonts and images are served from the site itself, so visiting doesn't send data to font or ad companies.

## Information saved on the student's own device

To make the site easier to use on a Chromebook, a few things are saved **in the browser on that device only**. We can't see them:

- **Staying logged in:** the student's code and first and last name, so they don't have to type the code every time. Students can untick "Keep me logged in" on shared computers, and **Log out** removes it.
- **Code drafts:** code typed into the Submit page, so it isn't lost if the page reloads. It's cleared after a successful submission.

## How we use information

We use information only to:

- run the class: plan lessons, take attendance, and contact families about the program;
- collect and store student work, and give feedback on it;
- show a student their own progress on the **My work** page;
- feature standout projects in the **Showcase** (see below).

We don't use student information for advertising, and we don't build profiles of students.

## The Showcase

Sometimes we feature a student's project on the public **Showcase** page. When we do, we show **only the student's first name**, and optionally their grade and the week, never a last name or contact details. A parent can ask us to remove a featured project at any time.

## Where information is stored

We use a small number of trusted services to run the program:

| Service | What it holds | Who can see it |
| --- | --- | --- |
| **Google** (Forms, Sheets, Apps Script) | Enrollment answers, the class roster and student codes, the submissions log and feedback | Program teachers only |
| **GitHub** (a private repository) | The code files students submit | Program teachers only |
| **GitHub Pages** | Hosts this public website | Public (contains no student personal information except Showcase first names) |

These services process data on our behalf under their own privacy policies (Google: policies.google.com/privacy, GitHub: docs.github.com/site-policy/privacy-policies). Like most web hosts, they may keep basic technical logs such as IP addresses to keep their services secure.

## Who can see student information

Only the program's teachers and organizers. We do **not** sell, rent, or trade personal information. We would share it only if required by law, or to protect a student's safety.

## How long we keep it

We keep enrollment information, student codes, and submitted work for the current school year so students can look back on their progress. After the program year ends, we delete or anonymize it within a reasonable time unless the family re-enrolls. We'll delete a student's information sooner if a parent asks.

## Keeping information safe

- Student work is stored in a **private** repository that only teachers can open.
- The website never stores or displays other students' information. A student code only shows that student's own work.
- Repeated wrong login codes are blocked, which makes codes impractical to guess.
- The keys that let the website save work are stored securely on Google's servers and never sent to anyone's browser.

No system is perfectly secure, but we take reasonable steps to protect the information we hold.

## Children's privacy

This program is designed for students roughly 12–16 years old. We collect student information **only with a parent or guardian's permission**, which is given on the enrollment form. Students under 13 don't create accounts with any outside service as part of this class.

## Your choices and rights

A parent or guardian can at any time:

- **see** the information we hold about their child;
- **correct** anything that's wrong;
- **delete** their child's information and withdraw from the program;
- **ask** us to remove a Showcase project.

Students should keep their student code private. If a code might have been shared, ask the teacher for a new one.

Email **faiyajr@umich.edu**, or talk to any madrasa teacher or staff member. We'll respond as soon as we can.

## Other websites

The site links to other websites, such as the online Python editor we use in class. Those sites have their own privacy policies, and we aren't responsible for how they handle information. We choose tools that don't require students to sign in.

## Changes to this policy

If we change this policy, we'll update the date at the top of this page. For important changes, we'll let families know directly.
